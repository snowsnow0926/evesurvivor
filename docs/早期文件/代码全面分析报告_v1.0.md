## 2. 严重 Bug（必须修复）

### Bug #1: `upgrade_menu.gd` — `apply_upgrade` 被调用两次 ⛔

**文件**: `scripts/upgrade_menu.gd`
**严重程度**: 🔴 严重 — 影响核心玩法数值

每次选择升级时，`game_manager.apply_upgrade()` 会被执行**两次**：

```
Button.pressed 信号
  → _on_btn_pressed() [第 194 行]
      → game_manager.apply_upgrade(upgrade_id)  ← 第1次
      → confirm_selection() [第 198 行]
          → _on_upgrade_selected() [第 226 行]
              → game_manager.apply_upgrade(upgrade_id)  ← 第2次
```

**后果**: 升级效果翻倍（加农炮+1额外子弹变成+2、伤害+20%变成+40%等）。

**修复方案**: 删除 `_on_btn_pressed` 中的 `game_manager.apply_upgrade` 调用（第 200 行），或删除 `confirm_selection` 中的调用，只保留一个入口。

---

### Bug #2: `spawn_manager.gd` — Boss 战可能无限刷 Boss ⛔

**文件**: `scripts/spawn_manager.gd` 第 159-166 行
**严重程度**: 🔴 严重 — 破坏游戏流程

```gdscript
if boss_remaining > 0:
    if kill_since_boss >= 50:
        _spawn_boss()
```

当 `boss_remaining == 0`（最终 Boss 已被击杀）后，`if boss_remaining > 0` 不满足，但随后的 `if kill_since_boss >= 50` 条件**未包含在 `boss_remaining > 0` 的分支内**。这意味着当 `BOSS_ONLY` 关卡且 `boss_count > 1` 时，如果击杀速度过快，可能导致 boss 刷新逻辑与 `boss_remaining` 递减不同步。

**修复方案**: 将 `kill_since_boss >= 50` 条件合并到 `if boss_remaining > 0` 内部。

---

### Bug #3: `game_manager.gd` — `is_boss_phase` 永远为 `false` ⛔

**文件**: `scripts/game_manager.gd` 第 298 行
**严重程度**: 🔴 严重 — Boss phase 逻辑永不触发

```gdscript
var is_boss_phase: bool = false  # 第 298 行
```

该变量在 `game_manager` 内部**从未被设为 `true`**。而 `spawn_manager` 有自己的 `is_boss_phase`（第 72 行），两个变量完全独立。第 285 行 `_on_timer_expired()` 检查 `game_manager.is_boss_phase` 的代码分支永远不会执行。

**修复方案**: 要么让 `game_manager` 监听 `spawn_manager.is_boss_phase` 变化，要么删除 `game_manager` 中的 `is_boss_phase` 相关逻辑，统一使用 `spawn_manager` 的版本。

---

### Bug #4: `boss_void.gd` — Boss 死亡时装备不掉落 ⛔

**文件**: `scripts/boss_void.gd` 第 140-146 行
**严重程度**: 🔴 严重 — 影响核心收益

Boss 的 `_die()` 覆盖：

```gdscript
func _die() -> void:
    _spawn_death_effect()
    enemy_dead.emit(self, "boss")
    spawn_boss_loot()  # 手动调用掉落
    queue_free()
```

与基类 `EnemyBase._die()`（第 436 行）对比：
- 基类: `enemy_dead.emit` → `_spawn_death_effect()` → `_on_death_rewards()` → `try_drop_equipment`
- Boss: `_spawn_death_effect()` → `enemy_dead.emit` → `spawn_boss_loot()` → **漏掉 `try_drop_equipment`**

Boss 死亡时 `game_manager.try_drop_equipment()` **不会被调用**。Boss 战利品只走 `spawn_boss_loot()`（货币+矿物掉落），但通过 `on_boss_killed` 路径的装备掉落被跳过了。

**修复方案**: 在 `boss_void._die()` 末尾添加 `try_drop_equipment()` 调用，或确保 `game_manager` 在 `enemy_dead` 信号处理中单独处理 boss。
