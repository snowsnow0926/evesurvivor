## 一、核心系统概述

### 1.1 什么是核心系统

核心（Core）是一个独立于种族和武器的新系统，每个种族对应一个专属核心，替代了旧版的三选一词条池 + 武器升级体系。

核心包含 **5 个词条**：
- **种族词条 ×3**（随核心解锁，每级 +1，上限 6 级）
- **通用词条 ×2**（全局生效，每级 +1，上限 6 级）

```
人类 → 导弹核心 → 火力覆盖 / 静默猎手 / 精准猎杀 + 伤害强化 / 临时护盾
兽人 → 加农核心 → 嗜血残暴 / 狂飙突进 / 为了部落 + 伤害强化 / 护盾充能
植物 → 磁轨核心 → 一发入魂 / 命中注定 / 多重射击 + 伤害强化 / 临时护盾
晶体 → 激光核心 → 高能光束 / 高效射击 / 护盾中和 + 伤害强化 / 护盾充能
```

### 1.2 等级上限

每词条等级上限固定 **6 级**，局内升级和局外升级共用同一上限（星际基地局外升级已禁用）。

## 二、核心系统架构

### 2.1 数据流

```
[游戏开始：选择种族]
        │
        ▼
CoreEquipManager.equip_starting_core(race)
        │
        ├── unlock_core() → CoreData { skill_levels }
        └── core_equipped.emit()
                 │
                 ▼
GameManager._on_core_equipped(core_id)
        │
        └── player_stats.sync_from_core()  ← 全量重算
                 │
                 ├── reset 所有核心相关字段为初始值
                 ├── 遍历 skill_levels，每级调用 _apply_upgrade_effect()
                 └── stats_changed.emit()
                          │
                          ▼
                 Player.sync_from_player_stats()
                          │
                          ▼
                 武器读取新属性值
```

### 2.2 关键文件

| 文件 | 职责 |
|------|------|
| `core_entry.gd` | 核心模板定义（静态数据） |
| `core_definitions.gd` | 所有词条的中英文名称、每级描述文案、显示颜色 |
| `core_registry.gd` | 核心模板查询接口（只读 Autoload） |
| `core_equip_manager.gd` | 核心装备核心状态管理器（可读写 Autoload） |
| `player_stats.gd` | 玩家属性计算（含 `sync_from_core` 全量重算） |
| `core_upgrade_center.gd` | 星际基地升级中心 UI |
| `game_manager.gd` | 监听信号并触发 `sync_from_core` |

### 2.3 组件关系

```
CoreRegistry (只读查询)
      ↑
CoreEquipManager (状态管理) ← CoreDefinitions (词条文案)
      │
      ├─ skill_upgraded 信号 ──→ GameManager._on_core_skill_upgraded()
      ├─ core_equipped 信号 ──→ GameManager._on_core_equipped()
      │
      └─ player_stats.sync_from_core() ──→ Player.sync_from_player_stats()
                                              │
                                              ▼
                                         各武器读取新属性
```

## 三、局内升级流程（核心替换旧系统）

### 旧系统（废弃）
- 种族天赋注入 `_race_talent_counts`
- 武器词条池（`weapon_data.gd` 中的 `upgrades`）
- 12 项研究系统

### 新系统
```
升级道具触发 UpgradeMenu
        │
        ▼
UpgradeMenu 调用 CoreEquipManager.get_available_upgrades()
        │
        ├── 从当前核心的 5 个词条中筛选 level < max_level 的项
        └── 随机取 3 项展示为三选一
用户选择 → CoreEquipManager.upgrade_skill()
        │
        └── skill_upgraded 信号 → GameManager._on_core_skill_upgraded()
                                         │
                                         └─ sync_from_core() → 属性立即生效
```

## 六、BUG 修复记录

| # | 问题 | 位置 | 修复内容 |
|---|------|------|----------|
| 1 | `_on_core_skill_upgraded` 写错变量，局内升级无效 | `game_manager.gd` | 替换为 `player_stats.sync_from_core()` |
| 2 | `core_equipped` 信号未连接，切换核心后属性不变 | `game_manager.gd` | 添加信号连接和 `_on_core_equipped()` |
| 3 | 双路径升级逻辑：旧系统降级路径绕过 CoreEquipManager | `game_manager.gd` | 简化为单一路径，无核心时才走旧系统 |

| 5 | 选择种族后进入游戏，仓库/升级中心核心显示锁定 | `character_create.gd` | `_on_confirm` 中存档前调用 `CoreEquipManager.equip_starting_core()` |
| 6 | 种族选择界面显示"默认武器"而非核心信息 | `character_create.gd` | 替换为"默认核心：XX + 核心技能列表" |
| 7 | 仓库 ShipInfoBar 无核心状态显示 | `warehouse_ui.gd` | 追加"核心: XX"信息 |
