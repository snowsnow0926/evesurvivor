# 核心系统架构设计

> 版本：v1.0 | 日期：2026-05-12 | 状态：待实现

## 一、设计目标

将「种族天赋」「局内三选一升级池」「科技升级（局外）」三个独立系统整合为统一的**舰船核心系统**，实现：

- 核心作为独立装备，与武器/防具同一套管理逻辑
- 种族选择后自动获得对应核心，开局即有成长路径
- 核心决定局内升级池，不再由装备武器决定
- 核心升级中心（原科研中心）统一管理局外升级
- 核心切换自由，进度独立保留


## 三、核心数据结构

### 3.1 CoreEntry

核心模板定义（全局静态数据），每个种族一份，存于 `resources/core_entry.gd`：

```gdscript
class_name CoreEntry
extends RefCounted

var core_id: String           # 唯一标识，如 "core_missile"
var core_name_zh: String      # 中文名，如 "导弹核心"
var core_name_en: String      # 英文名，如 "Missile Core"
var race: String              # 所属种族 "human"/"orc"/"plant"/"silicon"
var icon_id: String           # 图标ID（关联 icon_definitions.json）

# 词条池
var race_skills: Array[String]  # 种族专属词条ID列表（3个）
var universal_skills: Array[String]  # 通用词条ID列表（2个）

# 初始等级
var race_skill_start_level: int = 1   # 种族词条初始等级 = 1
var universal_skill_start_level: int = 0  # 通用词条初始等级 = 0
```

### 3.2 CoreData

玩家持有的每个核心实例数据，存于 `UserData`（存档）：

```gdscript
class_name CoreData
extends RefCounted

var core_id: String                    # 对应哪个核心模板
var skill_levels: Dictionary = {}      # { skill_id: int level }
var is_unlocked: bool = false          # 是否已解锁（掉落/购买获得）
var is_equipped: bool = false          # 是否已安装

# 显示名计算：
# 未升级 → CoreEntry.core_name_zh
# 升级过 → CoreEntry.core_name_zh + "+" + total_upgrade_count
#   total_upgrade_count = sum(skill_levels) - 天赋初始等级总和
#   （种族词条初始1级，通用词条初始0级，所以 +N = skill_levels value sum - 3）
```

### 3.3 存档结构（UserData 扩展）

```gdscript
# 在 UserData 中新增字段
var cores: Dictionary = {
    # core_id → CoreData
    "core_missile": CoreData,
    "core_cannon": CoreData,
    "core_railgun": CoreData,
    "core_laser": CoreData,
}
var equipped_core_id: String = "core_missile"  # 当前安装的核心ID
```

### 4.3 等级上限体系

```
每词条基础最高 = 6级（局内三选一满后封顶，不再出现选项）

  等级构成：
  ├── 天赋等级  = 1级（开局核心自带）
  └── 局内升级  = +5级（三选一升级，上限到6级后不再出现）

**等级关系**：
- 天赋等级 = 1级（开局核心自带，始终有效）
- 局内三选一升级 = +5级（从1级升到6级封顶，与局外升级独立）
- 局外升级（核心升级中心）= 在6级封顶基础上额外+2级（最高8级）
  - 局外升级不参与局内三选一逻辑，单独扩展等级上限
  - 核心升级中心升满后，词条最高可达8级
```

**关键说明**：局内三选一的升级不受局外升级影响。只要局内三选一还有次数（+5级），就可以继续升级直到6级。局外升级的作用是在6级之上额外扩展上限。

## 五、核心升级中心（原科研中心）

### 5.1 功能定义

- **位置**：星际基地界面，替换原科研中心
- **作用**：消耗星币 + 矿物，升级当前安装核心的词条等级上限
- **升级范围**：仅针对当前安装的核心（必须先持有并安装该核心）
- **升级效果**：每级 +1 词条等级上限（对应局外升级的 +2级分配到词条上）

### 5.2 升级消耗表

| 核心 | 词条 | Lv1→2 | Lv2→3 | 总消耗（封顶） |
|------|------|--------|-------|---------------|
| 所有核心 | 所有词条 | 200星币+200矿物 | 400星币+400矿物 | 600星币+600矿物 |

**注意**：核心升级中心的局外升级作用于词条的**等级上限扩展**，在6级封顶基础上额外+2级（最高8级）。局内三选一不受此限制，独立升级至6级。

### 5.3 升级前后界面变化

```
升级前词条状态（仅靠局内三选一升级）：
┌─────────────────────────────────────────┐
│ 🔵 火力覆盖        [■ □□□□□] Lv1/6      │
│ 导弹哒哒哒连射                              │
└─────────────────────────────────────────┘
  1个实心 = 1级(天赋)，5个空心 = 还能用局内三选一升5级到6级

升级后（三选一满级，局外扩展上限）：
┌─────────────────────────────────────────┐
│ 🔵 火力覆盖        [■■■■■■■■] Lv6/8      │
│ 导弹哒哒哒连射                              │
└─────────────────────────────────────────┘
  天赋1级 + 三选一5级 = 6级封顶；局外再扩展2级至Lv8
```

## 六、局内三选一升级

### 6.1 触发逻辑

- 玩家击杀敌人掉落经验球，拾取后积累经验值
- 经验值填满后**角色升级**，触发三选一
- 从**当前安装核心的词条池**中随机抽取3个可升级的词条
- 可升级条件：`当前等级 < 6`（6级封顶后该词条不再出现）

### 6.2 池子来源（核心绑定，废弃旧逻辑）

```
旧逻辑（废弃）：按当前装备武器类型决定升级池
  ❌ 多武器时只能取前2个 → BUG频发
  ❌ 切换武器后升级池变化 → 体验割裂

新逻辑（替换）：按核心词条池决定升级池
  ✅ 核心固定词条池 → 切换核心 = 切换升级路线
  ✅ 5个词条稳定可升级 → 不受武器数量影响
```

### 6.3 抽取规则

```
当前核心词条池 = 5个词条（3种族 + 2通用）

对每个词条检查：
  if current_level < max_level:
      加入候选池
  （max_level = 6级封顶，三选一升级到此为止）

从候选池中随机抽取 min(3, len(candidates)) 个展示
若候选池不足3个，则全部展示（少于3个选项时正常）
```

### 6.4 卡牌UI

沿用现有 `UpgradeMenu.tscn` 布局，核心系统只需要修改数据源（从 `Player.weapon_upgrades` 改为 `CoreEquipManager.get_current_pool()`）。

**名字后缀规则**：
- 未升级的核心：显示原名（如 `导弹核心`）
- 升级过的核心：`原名+N`（N = 所有词条累计升级次数总和）
  - 例：词条1升了2级，词条2升了1级，词条3-5未升 → `导弹核心+3`
  - 局内三选一升级 + 局外核心升级中心升级 均计入 N

### 7.3 安装/拆卸规则

| 操作 | 消耗 | 说明 |
|------|------|------|
| 安装核心 | 免费 | 从仓库选一个已解锁的核心安装 |
| 拆卸核心 | 免费 | 卸下核心放回仓库（进度保留） |

- 未解锁的核心（无核心数据/未获得）显示为锁定状态，不可安装
- 切换核心后立即生效，不重置任何进度

### 11.1 科研系统（完全废弃）

| 旧内容 | 废弃原因 | 新替代 |

### 11.2 三选一旧逻辑（完全废弃）

| 旧逻辑 | 废弃原因 |
