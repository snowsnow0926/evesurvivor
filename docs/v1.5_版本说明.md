## 二、敌人图标替换

### 设计动机

此前三种普通敌人（近战、哨兵、乌鸦）共用同一套多边形几何体，仅通过颜色区分，视觉区分度不足。本次更新引入 NPC 版舰船图标，让不同类型的敌人在视觉上有明显的吨位差异。

### 吨位分配

| 敌人类型 | 图标文件 | 对应吨位 | 死亡粒子颜色 |
|----------|----------|----------|--------------|
| EnemyMelee（近战） | `npcdestroyer_32.png` | 驱逐舰 | 红色 |
| EnemySentry（哨兵） | `npccruiser_32.png` | 巡洋舰 | 紫色 |
| EnemyRaven（乌鸦） | `npcfrigate_32.png` | 护卫舰 | 橙色 |

### 技术实现

- **图标来源**：复用 `resources/icon_definitions.json` 中已有的 NPC 舰船图标定义，在 `"enemies"` 分类下为三个敌人条目补全了 `texture_path` 字段
- **加载流程**：`EnemyBase._ready()` → `set_enemy_icon()` → 调用 `ShipIconGenerator.get_entry(Category.ENEMY, icon_id)` 加载 PNG 纹理到 `ShipSprite` 节点，隐藏原有 `Polygon2D`
- **Fallback**：若 `ShipIconGenerator` 返回 `null`（JSON 未定义或文件缺失），则 fallback 到 `ShipIconGenerator` 中注册的 SVG path 绘制多边形
- **朝向旋转**：新增 `_update_rotation()` 每帧以插值方式平滑旋转舰船朝向，旋转速度由 `_turn_speed` 控制（默认 4.0 rad/s）
- **图标尺寸**：与玩家舰船一致，使用 `ShipIconGenerator.ICON_SIZE`（80px）缩放渲染

### 效果预览

敌人从简单的纯色几何体升级为带有舰船细节的图标，不同吨位的敌人在尺寸和外形上有明显区分，提升了战场视觉丰富度。

## 三、敌人朝向跟随

### 设计动机

此前敌人的朝向固定不变，无法直观看出敌人面向哪个方向。引入平滑旋转后，敌人会始终朝向玩家，攻击方向一目了然。

### 实现细节

- `_current_angle`：记录当前朝向角度
- `_turn_speed`：转向插值速度，每秒最多旋转 4 弧度
- `angle_to_point(player)`：计算朝向玩家的目标角度
- 角度差做 `[-PI, PI]` 归一化后以 `minf(delta * _turn_speed, 1.0)` 插值平滑过渡

## 四、敌舰锁定系统

### 设计动机

模拟 EVE Online 中敌对舰船攻击前的锁定流程：发现目标 → 角框出现 → 锁定闪烁 → 锁定完成可以攻击。在游戏层面，锁定期间敌人无敌、静止，给予玩家反应时间。

### 锁定流程

| 阶段 | 状态 | 时长 | 表现 |
|------|------|------|------|
| 阶段一：锁定中 | `LOCKING` | 1.0 秒 | 黄色角框（两端延伸的 L 形，四角各一个）；敌人无敌、静止 |
| 阶段二：闪烁 | `FLASHING` | 3 次 × 0.25s = 0.75s | 黄色角框明暗闪烁；敌人仍然无敌、静止 |
| 阶段三：锁定完成 | `LOCKED` | 持续 | 角框变红，敌人图标染红；无敌解除，可被攻击；敌人开始正常移动和攻击；每次攻击角框闪烁一次（冷却 1.5s） |

### 角框设计

- **样式**：四角各一个 L 形角框（两条线段组成），arm 长度为敌人图标尺寸的 50%
- **颜色**：锁定中/闪烁阶段为黄色 `(1.0, 0.85, 0.0)`；锁定完成后为红色 `(1.0, 0.2, 0.2)`，乌鸦在 windup 期间为橙色 `(1.0, 0.5, 0.0)`
- **渲染**：通过 `_draw()` 每帧绘制，不依赖额外节点
- **攻击闪烁**：角框透明度从 0.3 渐变到 1.0，持续 0.2s，冷却 1.5s

### 技术实现

- **状态机**：`LockState` 枚举管理三个阶段，`_update_lock()` 每帧驱动状态转换
- **纹理预生成**：`_ready()` 时生成两张纹理缓存——`_icon_tex`（原始）、`_locked_tex`（染红），避免每帧重复处理
- **无敌判定**：`take_damage()` 中通过 `_is_locked` 标志忽略锁定期间所有伤害
- **移动/攻击屏蔽**：`LOCKING` 和 `FLASHING` 状态下 `_physics_process` 不调用 `_update_movement()` 和 `_process_combat()`
- **子类钩子**：提供 `get_locked_bracket_color()`、`is_windup_state()` 等虚方法，供 Raven 等特殊行为子类覆盖

### 攻击闪烁时序

```
锁定完成 → cooldown = 1.5s → cooldown = 0 → 可再次闪烁
    ↓
触发攻击 → flash_timer = 0.2s → 角框 alpha: 0.3 → 1.0
    ↓
flash_timer = 0 → cooldown 重置为 1.5s
```

### 特殊处理：Raven

Raven 有独立的爆炸前摇（windup）闪烁，与锁定流程共存：
- windup 期间整个敌人图标明暗闪烁（隐藏/显示），不影响角框
- 角框保持橙色，与粒子特效配色一致
- 覆盖 `is_windup_state()`、`get_locked_bracket_color()` 等虚方法

### 常量参数

| 常量 | 默认值 | 说明 |
|------|--------|------|
| `LOCK_DURATION` | 1.0s | 锁定中阶段持续时间 |
| `FLASH_INTERVAL` | 0.25s | 闪烁周期 |
| `FLASH_COUNT` | 3 | 闪烁次数 |
| `ATTACK_FLASH_INTERVAL` | 1.5s | 攻击闪烁冷却时间 |
| 攻击闪烁时长 | 0.2s | 角框透明度从 0.3 渐变到 1.0 |

## 五、背景与星空修复

### 问题描述

游戏加载时全屏无黑色背景，且三层星空粒子特效仅显示一层。

### 修复方案

#### 1. 添加全屏黑色背景层

在 `GameScene.tscn` 中于根节点下新增 `CanvasLayer`（layer=-100），其下添加 `ColorRect` 全屏覆盖，颜色为 `(0, 0, 0.02, 1.0)`（近乎纯黑）。通过设置极低的 layer 值确保背景始终在最底层。

#### 2. 恢复三层视差星空

`ParallaxStarfield` 节点脚本恢复为原始逻辑：
- **节点跟随相机**：`position = camera.global_position` 确保星星始终以玩家为中心
- **三层星空参数**：

| 层 | 视差 | 密度 | 颜色 |
|----|------|------|------|
| 1  | 0.15 | 130.0 | 淡蓝白 (0.7, 0.8, 1.0) |
| 2  | 0.35 | 90.0  | 冷白 (0.85, 0.9, 1.0) |
| 3  | 0.60 | 55.0  | 暖白 (1.0, 0.95, 0.85) |

- **圆形视野裁剪**：以屏幕中心为圆心、半径为屏幕对角线×0.8 的圆形范围内才渲染星星，超出部分跳过，减少 draw call
- **视差效果**：远处星星（低视差 0.15）移动慢，近处星星（高视差 0.60）移动快，形成层次感
- **闪烁效果**：每颗星星有独立的闪烁频率和相位偏移

#### 3. 技术细节

- 星星预生成在 [-5000, 5000] 范围内，共约 2080 颗，性能友好
- `spread = 5000`，每颗星随机位置，大小 0.8~2.2px
- `_draw()` 每帧调用，`process_physics_priority = -100` 确保晚于物理处理
- `queue_redraw()` 在 `_physics_process()` 中触发
